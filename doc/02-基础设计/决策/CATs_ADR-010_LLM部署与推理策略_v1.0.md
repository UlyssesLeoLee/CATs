## 1. 背景

CATs 核心能力是"AI 增强型翻译"，LLM 推理是命脉。ADR-001 已落定 `llm-gateway` 微服务，ADR-003 已落定 PG 中心化存储，但"LLM 部署形态"未决策。

CATs 面对两类需求：

- **合规项目**(政府 / 金融 / 医疗行业翻译)：要求"数据不出域"，推理必须在客户私有环境或本地数据中心
- **非合规项目**(通用商业翻译)：追求模型质量与成本最优，可接受公有云 API

QA-051 已登记为 Open 项，要求 LLM 部署策略明确。QA-003(整体合规需求)与之强相关。要决策：

- **推理形态**：本地自托管 vs 公有云 API vs 混合
- **模型选型**：开源(Qwen2.5 / Llama 3 / DeepSeek)vs 闭源(GPT-4o / Claude 3.5)
- **硬件预算**：单卡 / 多卡 / H100 集群
- **统一接入层**：网关抽象模型与部署形态解耦

## 2. 选项

| 选项 | 描述 | 优势 | 劣势 |
|------|------|------|------|
| **A. 全本地自托管** | vLLM + 开源模型，全部流量走本地 | 数据完全可控、无 API 成本、可深度定制 | 硬件投入大、模型质量受限、SRE 需 GPU 运维能力 |
| **B. 全公有云 API** | 全部走 OpenAI / Anthropic API | 模型质量最高、零运维、弹性无限 | 合规项目不可用、数据出域、成本随用量线性增长 |
| **C. 混合：合规本地 + 非合规云端** ✅ | 合规项目走本地 vLLM + Qwen2.5-7B-Instruct 量化版；非合规走 OpenAI / Anthropic 通过 LiteLLM 统一 | 兼顾合规与质量、SRE 只运维本地集群、模型可换 | 网关需双路径、监控 / 计费需双维度 |
| **D. 全本地 + 多卡 H100** | 8×H100 自托管 70B 模型 | 质量最高 | 硬件成本 ~$300K、SRE 2 人无法运维、ROI 不匹配 M3 时间线 |

补充说明：

- 选项 D 与 NFR-OP-010(SRE 2 人 ≤ 20 人·天/周)冲突，且 8-25 评审会预算不批
- 选项 C 是 CATs 实际客户分布的必然选择(已有 3 个合规项目 RFP 在跟进)
- 本 ADR 决策"混合 + LiteLLM 统一接入"，对应选项 C

## 3. 决策

**采用 C：合规项目走本地 vLLM + Qwen2.5-7B-Instruct(AWQ 量化版) + 单卡 24GB RTX 4090；非合规项目走公有云 OpenAI / Anthropic API；通过 LiteLLM 统一接入。**

实施细则：

1. **本地推理集群(合规项目)**
   - 模型：Qwen2.5-7B-Instruct-AWQ(4-bit 量化，~5GB 显存占用)
   - 推理框架：vLLM 0.6.x(支持 AWQ、连续批处理、PagedAttention)
   - 硬件：单台 24GB RTX 4090 工作站起步，可横向扩 2-4 台
   - 部署：K8s GPU Node + taint 隔离，仅 `llm-gateway` 调度
2. **公有云推理(非合规项目)**
   - 主用：OpenAI `gpt-4o-mini`(成本可控)
   - 高质量场景：Anthropic `claude-3-5-sonnet`
   - 通过 LiteLLM Proxy 抽象为 OpenAI 兼容协议
3. **统一接入层 `llm-gateway`**
   - 协议层：内部 gRPC(参见 ADR-002)+ 对外 OpenAI 兼容 REST
   - 路由策略：项目级配置 `compliance_mode` 决定走本地还是云端
   - 配额：云端 API 按租户配额计费(参见 ADR-005 多租户)
4. **Fallback 链**
   - 云端故障 → 降级到本地(若项目允许)；本地故障 → 返回明确错误，不静默回云端
5. **可观测**
   - 指标：`llm_request_total{deployment="local|cloud",model="..."}`、`llm_token_total{...}`、`llm_latency_seconds{...}`
   - 成本面板：云端 API 按租户聚合，写入 `billing` 域
6. **模型升级路径**
   - M1 锁 Qwen2.5-7B-Instruct-AWQ
   - M3 评估 Llama 3.1-8B-Instruct / DeepSeek-V2-Lite 作为备选
   - 升级需双周评估窗口 + A/B 测试流量切 10% → 50% → 100%

## 4. 影响

- **正面**：
  - 合规 RFP 可立即响应(本地路径已就绪)
  - 非合规项目享受云端模型质量上限
  - LiteLLM 抽象层使模型可换 → 不锁定单一供应商
  - 单卡 RTX 4090 起步成本 < ¥30K，硬件预算可控
- **负面**：
  - 网关需维护双路径配置(本地 + 云端)，配置文件治理复杂
  - 云端成本随用量增长 → 需预算红线 + 告警(已在 billing 域规划)
  - 本地 GPU 节点 SRE 需新技能(已列入 8-25 评审会培训议程)
- **风险**：
  - Qwen2.5-7B 翻译质量弱于 GPT-4o-mini → 客户可能反馈翻译质量差异 → 需在合规项目交付时透明披露
  - GPU 供应链紧张 → RTX 4090 备货周期 4-6 周，需提前下单
  - 云端 API 涨价 / 服务商政策变化 → LiteLLM 抽象降低切换成本
  - 合规审计要求"推理可复现" → 本地路径已天然支持，云端需记录 API 请求/响应快照
