## 1. 目的

定义 CATs 系统的**用户验收测试（UAT）**计划，作为：

- 受入判定（任务 94）的依据
- 検収（任务 95）的输入
- 客户/产品主导的验收基线
- 上线 Gate（Go-Live）的最后一道关

---

### 2.1 包含

| 类别 | 范围 |
|------|------|

### 5.2 端到端业务场景

| **场景 6：版本回滚** | 编辑 → 保存版本 → 修改 → 回滚 → 验证 | 数据一致 |

## 6. 通过准则

### 6.1 整体通过

| 维度 | 通过线 |
|------|--------|
| 用例通过率 | ≥ 95% |
| P0 缺陷 | 0 |
| P1 缺陷 | 0（残留需明确豁免） |
| P2 缺陷 | ≤ 5（可豁免至上线后） |
| 业务场景 | 全部通过 |
| 性能 | 全部 NFR 达标 |
| 客户满意 | ≥ 4.0 / 5.0 |

### 6.2 不通过条件

- 任一 P0 缺陷未关闭
- 业务场景失败
- 性能不达标
- 数据不一致
- 客户拒收

### 6.3 豁免机制

- 客户可豁免 P2 缺陷（记录 + 上线后修复）
- P1 缺陷需 Sponsor + 客户双方签字
- P0 缺陷不可豁免

---

## 7. 缺陷管理

### 7.1 流程

```
UAT 执行 → 发现缺陷 → 记录（issue-svc）→ 严重度分级 → 通知 → 修复 → 回归 → 关闭
```

### 7.2 严重度

| 级别 | 含义 | SLA |
|------|------|-----|
| P0 | 阻塞 / 数据丢失 | 立即响应 / 4h 修复 |
| P1 | 主流程不可用 | 1d 修复 |
| P2 | 非主流程问题 | 3d 修复 |
| P3 | 体验问题 | 上线后修复 |

### 7.3 修复 vs 豁免

| 严重度 | UAT 期修复 | 豁免 |
|--------|-----------|------|
| P0 | 必修复 | 不可豁免 |
| P1 | 必修复 | 客户 + Sponsor 双方签字 |
| P2 | 优先修复 | 客户单方签字 |
| P3 | 列入 backlog | 客户单方签字 |
