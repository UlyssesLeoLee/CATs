## 7. ST 专项结果汇总

### 7.1 性能专项（子报告 A）

详见 [CATs_性能試験（PT）レポート テンプレート v1.0](./CATs_性能試験（PT）レポート_テンプレート_v1.0.md)，本期实测关键结论：

- **达成**：13/14 项 SLO（仅 L2 修复后达成）
- **瓶颈**：LiteLLM retry 退避（已修）、WS Yjs 压缩（已修）、ffmpeg 字幕烧录 I/O（已加 buffer pool）
- **风险**：单任务 4K 视频（> 60min）未压测，列入 M5 跟踪项 R-PT-007

### 7.2 安全专项（子报告 B）

详见 [CATs_セキュリティ試験レポート テンプレート v1.0](./CATs_セキュリティ試験レポート_テンプレート_v1.0.md)，本期实测关键结论：

- **SAST 扫描**：semgrep + bandit + cargo-audit = 0 高危、2 中危（已豁免计划）
- **DAST 扫描**：OWASP ZAP baseline 0 高危
- **SBOM**：syft + grype 扫描 312 组件，0 严重漏洞
- **渗透专项**：JWT 签名攻击、Idempotency-Key 滥用、SQL 注入、SSRF、跨租户访问 — 全部 100% 拦截
- **残留风险**：2 中危（gRPC debug 端口在 PRE 暴露 + 旧版 transitive dep），豁免至 M3 上线前修复

### 7.3 障害 / 故障注入专项（子报告 C）

详见 [CATs_障害試験レポート テンプレート v1.0](./CATs_障害試験レポート_テンプレート_v1.0.md)，本期实测关键结论：

| 场景 | 工具 | 验证结果 |
|---|---|---|
| ① 单微服务 Pod 重启 | `kubectl delete pod` | 任务从中断点继续推进，RTO < 30s ✅ |
| ② Kafka broker 短暂不可用（< 5min） | 手动 stop broker | 事件最终一致送达，0 丢失 ✅ |
| ③ Debezium connector 重启 | `kubectl delete pod` | LSN 推进不丢失 ✅ |
| ④ PostgreSQL 主节点宕机 | `pg_ctl stop` | 自动 failover，业务中断 18s < SLO ✅ |
| ⑤ 客户端断网 | `tc netem` 丢包 30% | 离线队列累计 + 恢复后无重复 ✅ |
| ⑥ 本地 LLM 不可达（合规项目） | 模拟宕机 | fail-closed，错误码 `COMPLIANCE_BLOCKED` 100% ✅ |
| ⑦ K3s 控制面 1/3 节点宕机 | 手动 stop etcd | 集群仍可调度 ✅ |
| ⑧ Harbor 不可用 | 模拟 Harbor 宕机 | 已运行 Pod 不受影响 ✅ |
