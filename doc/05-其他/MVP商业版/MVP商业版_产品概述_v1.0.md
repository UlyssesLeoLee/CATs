## 1. Elevator Pitch（一段话讲清楚）

CATs（Computer-Assisted Translation Suite）是一套面向企业级翻译团队与本地化工程师的 **全媒体 AI 辅助翻译 SaaS 平台**。它在保留传统 CAT 工具（Trados/MemoQ/OmegaT）核心优势 —— 翻译记忆库（TM）、术语库（Glossary）、质量保证（QA）—— 的同时，把翻译能力从纯文本扩展到**音频、视频、PDF、Office、图文、动图**等全媒体形态，并由 **LangGraph 编排的多模型 LLM** 自动完成 80% 的初译 + 术语一致性校验 + 标签保护，人工只需做最后 20% 的润色与终审。

**一句话总结**：CATs = 全媒体 AI 辅助翻译 SaaS = Trados 的翻译质量 × 多模态扩展 × LLM 自动化 × 私有化部署友好。

## 2. 核心特性（5 个）

### 2.1 全媒体翻译（Not just text）

| 媒体类型 | 输入 | 输出 | 关键能力 |
|---|---|---|---|
| 文本 | .txt / .md | .txt / .md | TM 匹配、术语注入、QA |
| Office | .docx / .xlsx / .pptx | 同格式（保留版式）| LibreOffice Headless 转换 + python-docx/openpyxl/python-pptx |
| PDF | .pdf（可复制/扫描） | .pdf（双语对照） | PaddleOCR + 版面保留 |
| 音频 | .mp3 / .wav / .m4a | .srt / .vtt / .ass + 烧录视频 | faster-whisper ASR + 时间轴对齐 |
| 视频 | .mp4 / .mov / .mkv | .mp4（字幕烧录）+ .srt | ffmpeg 抽帧 + ASR + 字幕烧录 |
| 图文 | .gif / .webp | 同格式（翻译后保留动效） | ffmpeg 抽帧 + PaddleOCR 逐帧 + Pillow 重编码 |

**客户痛点**：传统 CAT 工具只能翻译纯文本，多媒体翻译需要外购 ASR/OCR 服务 + 自研管道，集成成本 6-12 人月。CATs 一套搞定。

### 2.2 翻译记忆库（TM）与术语库（Glossary）强一致性

- **TM 三级匹配**：exact_match（精确）/ fuzzy_match（模糊 ≥ 75%）/ semantic_match（pgvector 语义召回 ≥ 0.82 余弦相似度）
- **术语库 enforcement**：术语命中强制替换，例外需 Sponsor 审批
- **跨项目共享**：同一 Org 下术语库可被多个项目复用
- **TM 自动回存**：人工确认后的译文自动入库，TM 命中率随项目推进单调递增

**客户痛点**：Trados/MemoQ 的 TM 是文件级（.sdltm/.tmx），团队协作需手工同步；CATs TM 是数据库级（PostgreSQL + pgvector），实时共享、版本可追溯。

### 2.3 合规 fail-closed（敏感项目本地模型兜底）

- **策略维度**：客户级（合规域）→ 项目级（敏感项目标记）→ 任务级（实时生效）
- **敏感项目强制本地 LLM**：策略命中 → translation-core → ai-gateway 仅允许本地 vLLM/TGI 推理
- **本地不可达 = 直接拒绝（fail-closed）**：绝不降级到云端 API（合规 fail-closed 是硬底线）
- **审计可追溯**：每次模型调用记录 model_id / token_count / trace_id，落 audit_db 永久保存

**客户痛点**：金融、医疗、法律、政府客户最关心数据不出局域网。CATs 是少数把 fail-closed 写进架构原则（不是策略层）的 CAT 工具，参见《CATs 微服务架构设计书 v1.0》§1.2 设计原则 #3。

### 2.4 离线模式 + 断网恢复（局域网场景刚需）

- **Tauri 客户端本地缓存**：TM 段、术语、当前任务进度都缓存到 SQLite
- **离线可编辑**：断网状态下 TM/术语查询、译文编辑、QA 检查全部本地可用
- **联网自动重放**：离线期间的编辑操作进本地队列，恢复联网后按 FIFO 自动同步
- **冲突解决**：最后写入获胜 + 审计日志记录冲突点，人工裁决

**客户痛点**：制造企业、政府机构、出海差旅翻译员都遇到过"翻译到一半断网"——CATs 把这个场景从"灾难"变成"无缝"。

### 2.5 私有化部署友好（局域网 / 离线 / 镜像自托管）

- **K3s 单集群部署**：1 控制面 + N 工作节点即可起步，50-3000 并发用户
- **离线镜像仓库**：Harbor 自托管，全部 Docker 镜像可离线分发
- **数据库即真相**：PostgreSQL 18.6 + pgvector 0.8.6 是唯一权威存储；Kafka/Valkey 仅做事件/缓存，可选
- **GitOps 声明式部署**：Argo CD + Gitea Actions，配置即代码，分钟级回滚

**客户痛点**：SaaS 翻译工具的"私有化版"通常是阉割版（少 TM、少术语、无 ASR），CATs 商业版与 SaaS 版**同代码同版本**，私有化部署零功能损失。

## 3. Use Case（3 个典型场景）

### 3.1 游戏本地化公司：从代码仓库到多语言上线

| 阶段 | 客户动作 | CATs 能力 |
|---|---|---|
| 1 | 上传 .json/.csv/.po 翻译资源 | ingestion-service 识别编码/语言 |
| 2 | 配置项目语言对（en→zh-CN/ja/ko）+ 术语库 | project-service 持久化术语 |
| 3 | 批量启动翻译任务 | task-service 异步编排，translation-core 跑 LangGraph |
| 4 | 翻译员审校 | Tauri 客户端 overlay 编辑 + 行内 QA |
| 5 | 导出回代码仓库格式 | render-writer-service 还原 .json/.csv/.po |

**业务价值**：1 人日处理 5000 字符串（含 LLM 初译 + 人工润色），错误率 < 0.5%。

### 3.2 跨境电商：商品详情页 + 评论 + 客服工单全翻译

| 阶段 | 客户动作 | CATs 能力 |
|---|---|---|
| 1 | API 接入 SKU 详情页（每日 10w 条） | batch translate API + 幂等键 |
| 2 | TM 自动匹配（命中率 60% 起步） | pgvector 语义召回 |
| 3 | LLM 翻译新 SKU（40%） | translation-core + ai-gateway |
| 4 | 翻译员抽检 5% | Tauri 客户端抽样审校 |
| 5 | 写回源系统 | task-service 完成事件 → 回调 API |

**业务价值**：1 名翻译经理 + 1 名翻译员可支撑日均 10w SKU 多语言上线。

### 3.3 出海差旅翻译员：手机 + 笔记本移动办公

| 阶段 | 客户动作 | CATs 能力 |
|---|---|---|
| 1 | 飞机上翻译 PDF 合同 | 离线模式：TM + 术语本地命中 |
| 2 | 落地后联网自动同步 | 离线队列重放 + 冲突解决 |
| 3 | 客户现场润色 | Tauri 客户端 overlay 编辑 |
| 4 | 客户签字后导出双语 PDF | render-writer-service PDF 烧录 |

**业务价值**：差旅期间业务不中断，落地后零手工同步成本。

## 5. 部署形态

### 5.1 SaaS（多租户托管）

- **接入**：`https://app.cats.example.com`
- **付费**：按 Org 订阅 + 用量阶梯计费
- **运维**：CATs 运营团队全托管，含 SLO/告警/扩容
- **适合**：中小翻译团队、轻量本地化需求

### 5.2 私有化（局域网部署）

- **接入**：客户局域网内 `https://cats.<customer>.internal`
- **付费**：一次性 License + 年度服务费
- **运维**：客户 SRE 团队自托管，CATs 提供安装手册 + Runbook + Hypercare 4 周
- **最小配置**：1 控制面（4C8G）+ 2 工作节点（8C16G）+ 1 NAS（1TB）
- **推荐配置**：3 控制面（HA）+ 5 工作节点（标签分池：general/media-cpu/media-gpu/data）+ 10TB NVMe
- **适合**：金融/医疗/政府/制造/游戏大厂/出海团队

### 5.3 混合云（专线回流）

- **接入**：客户专网 → CATs 私有云
- **付费**：订阅 + 专线费用
- **运维**：CATs 运营 + 客户 SRE 联合值守
- **适合**：跨境集团、跨国研发中心
