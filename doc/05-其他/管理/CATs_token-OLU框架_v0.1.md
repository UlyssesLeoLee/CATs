## 1. 背景与目的

### 1.1 传统"人·天"单位的局限

CATs 项目管理计划书 v1.0 §7.1 资源计划以"人·月"为单位（峰值 9.5 / 均值 8.6 / 预算 138 人·月）。该单位隐含假设：

- 工作日 = 8 小时有效产出
- 人类工作日含会议 / 上下文切换 / 决策等待等开销
- 工作产出 = 单位时间 × 经验系数

**AI 协作开发场景下，假设不成立**：

- AI 在上下文窗口内可秒级生成数百行 Rust 代码
- 人类工作日含会议 / 上下文切换 / 决策等待等开销（AI 不存在）
- AI 协作速度与人类工作日非线性对应

> per 2026-08-21 Ulysses 强证据："我是使用 AI 开发，这个时间和人类不同，应该采用 token 算开发量"

### 1.2 引入 token 单位的合理性

- **精度对齐**：token 与"上下文窗口 / 单次会话成本 / 决策质量（多轮对话）"等 AI 协作实际约束直接相关
- **跨项目可比**：RGS / Physis / Star 等项目均采用 AI 协作，统一 token 单位便于跨项目资源对比
- **避免人天误用**：Sprint 1 估时（如 Rust Lead 900K-1.55M tokens / 架构师 Lead 1.03M-1.92M tokens）若折算为"人·天"，会得到 3-15 人·天，与"一人公司 1 人"实际能力严重脱节

### 1.3 v0.1 不解决

- **不取代人·月总预算**：项目管理计划书 §7.3 138 人·月总预算仍以"人·月"为口径，本框架仅作为 Sprint 内部 + 跨域 Lead 间资源分配单位
- **不取代工时表**：一人公司 = Ulysses 兼任 12 角色，工时表不实际填报（per DEC-008）；本框架仅在 Sprint 拆解 + 评审材料中应用
- **不解决跨项目 OLU 同步**：RGS-TS-001 §6.2 草案不在本 worktree，跨项目同步需 OI-6 决议 8（T-03 借机）扫三仓基线后展开
- **不解决非 AI 协作任务**：客户对接 / 合同 / 财务等非 AI 协作任务仍以"人·天"计（per §6.3 已知缺口）

## 2. 单位定义

### 2.1 三单位基础

| 单位 | 等价 token 区间 | 用途 | 备注 |
|------|----------------|------|------|
| **1 人·天** | 100K-300K tokens | Sprint 任务估时单位 | 含输入 + 输出 + 决策对话 + 验证往返 |
| **1 人·周** | 500K-1.5M tokens | Sprint 阶段估时单位 | 5 工作日 × 100K-300K |
| **1 SRE 上限** | 1M tokens/周 | 个人产能上限 | 5 域 Lead 中瓶颈 Lead 上限参考 |

> **区间而非定值**：100K-300K 是参考区间，实际任务估时落点取决于任务复杂度、上下文长度、决策密度等。

### 2.2 token 包含范围

| 项 | 是否包含 | 备注 |
|----|---------|------|
| **输入 token** | ✅ | 用户消息 + 附件 + 工具结果 |
| **输出 token** | ✅ | AI 生成内容 |
| **决策对话 token** | ✅ | 多轮澄清 + 选项对比 + 拍板 |
| **验证往返 token** | ✅ | 编译错误 → AI 修正 → 重编译 |
| **DDD Review token** | ✅ | 评审材料 + 评论 + 修订 |
| **commit message token** | ✅ | git 提交说明 |
| **历史上下文回溯** | ⚠️ 部分 | 旧 worktree 调取按实际计入 |
| **外部 API token**（如 web_search）| ❌ 不计 | 外部资源消耗单算 |
| **人脑会议时长** | ❌ 不计 | 非 AI 协作部分 |

### 2.3 与人·月总预算的换算

| Sprint 估时 | 等价人·月 | 备注 |
|------------|----------|------|
| 1.85M-3.5M tokens | 1.85-3.5 人·月 | M1-Sprint 1 v1.0+2 估时合计 |
| 60M-120M tokens | 6-12 人·月 | M1-Sprint 1-3 全期估时（per 启动会 §3 估时范围）|
| 138 人·月 | ≈ 690M-1.38B tokens | 项目管理计划书 §7.3 总预算等价 |

> **138 人·月总预算不变**（Sponsor 决策），本框架仅在 Sprint 内 + 跨域 Lead 间资源分配时使用 token 单位。

## 3. 5 域 Lead 系数区间

### 3.1 系数总览

| 角色 | 单任务估时区间 | 适用任务特征 | 1 周上限参考 |
|------|---------------|------------|------------|
| **架构师 Lead** | 150K-300K tokens | 文档 / 设计 / 评审材料 | 1M tokens |
| **Rust Lead** | 250K-450K tokens | 代码 / 编译 / e2e 测试 | 1.5M tokens |
| **DBA Lead** | 200K-350K tokens | DDL / SQL / EXPLAIN / 索引 | 1M tokens |
| **QA Lead** | 200K-400K tokens | 测试用例 / 集成测试 / 报告 | 1M tokens |
| **PMO Lead** | 100K-200K tokens | 文档治理 / 模板 / 复盘 / 议程 | 500K tokens |
| **SRE 平台 Lead** | 50K-100K tokens | CI 配置 / 镜像 / 集群支持 | 300K tokens |

### 3.2 系数确定依据

| 角色 | 系数偏高原因 | 系数偏低情形 |
|------|------------|------------|
| **架构师 Lead** | 文档化任务需大量修订；DDD Review 6 角色循环 | 简单 ADR / 模板套用（PMO 化）|
| **Rust Lead** | 代码生成量大；编译往返多；e2e 调试 token 密集 | CRUD stub 模板（一次性产出）|
| **DBA Lead** | DDL 需精确；EXPLAIN 多轮；索引建议需验证 | 现有 schema 复用 |
| **QA Lead** | 测试用例设计细致；集成测试 mock 链长 | 简单冒烟用例 |
| **PMO Lead** | 文档治理多模板化；估时较稳定 | 模板已落地（节省 token）|
| **SRE 平台 Lead** | 涉及外部系统对接；token 不可控 | 复用现有 CI 配置 |

### 3.3 5 域 Lead 严格不混用（per 2026-08-21 决议）

- **架构师 Lead 估时** 不挪用 Rust / DBA 域 token
- **Rust Lead 估时** 不挪用 DBA / QA 域 token
- 共同责任（如 T-07 决议 10 错误码闭环涉及架构师 + Rust）按主责任 Lead 80% / 共同责任 Lead 20% 拆分，**不重复计**
