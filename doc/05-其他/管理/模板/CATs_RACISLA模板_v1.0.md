## 3. SLA 定义

### 3.1 三档响应时效（per 启动会决议 4 通过方案 A）

| 档位 | 时效 | 适用 | 触发方式 |
|------|------|------|----------|
| **默认档** | **24h**（工作时间）| 所有 RACI C 角一般咨询 | 任务 R 在 RACI 表中向 C 发起咨询 |
| **紧急档** | 8h（工作时间）| 阻塞任务主线 / 阻碍 Gate 通过 / 客户紧急 | R + A 联合签发"紧急咨询"标记 |
| **PMO 升级档** | 立即（≤ 1h 启动裁决）| SLA 违约 / 5 域 Lead 决策冲突 / Sponsor 介入 | PMO Lead → Sponsor 直线升级 |

### 3.2 工作时间口径

| 项 | 定义 |
|----|------|
| **工作时间** | 周一 ~ 周五 09:00-18:00 JST（日本标准时间） |
| **响应起点** | 咨询发出时刻（如 18:00 后发出，次日 09:00 起算） |
| **响应终点** | C 角实质回复（review 结论 / 决策 / 提问均可，**不要求 24h 内完成实际工作**） |
| **周末 / 祝日** | 不计入工作时间（紧急档走 PMO 升级） |
| **连续休假** | 提前 1 工作日通知 PMO Lead，自动延期（最长 5 工作日） |

### 3.3 "回复" 的最低标准

C 角回复至少包含以下任一项：

1. **实质性回答**：直接答复咨询问题（含引用文档/代码位置）
2. **决策结论**：给出 R/A 可执行的决定（"同意 / 拒绝 / 改 X 路径"）
3. **澄清问题**：要求 R 进一步澄清（澄清后 SLA 重新起算，最多 2 轮）
4. **升级通知**：明确告知"本咨询需升级 PMO / Sponsor"，并 @PMO Lead

**不算回复**的情形（视为 SLA 违约）：

- 仅"已收到" / "待看" / 无内容
- 沉默超过 SLA 时效
- 委托给无授权的第三方（如 R 委托给非 C 角角色）

## 4. 违约处理

### 4.1 违约识别

| 情形 | 识别方式 |
|------|----------|
| 沉默超过 24h（默认档）| R 在 RACI 表备注 "SLA 违约 @C 角色" |
| 沉默超过 8h（紧急档）| 同上，立即升级 |
| 回复不合 §3.3 标准 | R 反馈 PMO Lead，PMO 重新发起 SLA 计时（≤ 2 轮） |

### 4.2 违约处理路径

```
SLA 违约 (R 识别) → PMO Lead 收到 → 24h 内裁决：

  ├─ 轻违约（首次 + 咨询低优先级）→ PMO 提醒 C 角 + 记录到 Sprint 复盘
  ├─ 中违约（2 次或阻塞任务主线）→ PMO 升级 Sponsor + 5 域 Lead 现场裁决
  └─ 重违约（紧急档违约 / 多次）→ Sponsor 直接换 C 角 / 拆任务 / 改 RACI
```

### 4.3 违约记录

- 每 Sprint 末（T-07 复盘时）统计 SLA 违约次数
- 3 次以上违约的 C 角触发 RACI 重新分配评审
- 违约记录作为 PMO 月度报告附录

## 5. 模板使用指引

### 5.1 在 Sprint 任务拆解 RACI 表中引用

每张 RACI 表（如 Sprint 1 拆解 §4）末尾加：

```markdown
> **Consulted 角响应 SLA**：本表 C 角响应时效遵循
> `doc/05-其他/管理/模板/CATs_RACISLA模板_v1.0.md` §3 默认档 24h
> （紧急档 8h / PMO 升级档 ≤ 1h 启动）。
> 违约处理：见 §4。Sprint 1 DDD Review 期内如有调整，
> 走 v1.0+1 升版流程。
```

### 5.2 在评审会议程中引用

评审会议程（如启动会议程 §议程 N）涉 RACI SLA 时：

```markdown
> 本议程 RACI 适用 `CATs_RACISLA模板_v1.0.md` §3
```

### 5.3 不复用本模板的场景

| 场景 | 应使用 |
|------|--------|
| 评审会 D-Day 6 角色签字 | 评审会决议流程（per BD 评审纪要）|
| CAB 决议 | CAB 章程（per 项目管理计划书 §12.2）|
| Sponsor 直接裁决 | Sponsor 直裁流程（Sprint 2 单独定义）|
| 客户业务咨询 | BA 客户沟通矩阵（per 工作流文档 §5.1）|

### 6.2 跨项目 RACI SLA 同步未完成

- 决策 5 token-OLU v0.1 立项时涉及 RGS / Physis / Star 三仓基线同步
- RACI SLA 是否跨项目统一（24h 一致 vs 各项目自定义）未决议
- **建议**：OI-6 跨项目同步时（决议 8 / T-03 借机）扫 3 仓 RACI 现状
- **当前状态**：CATs 仓内 24h 默认；跨项目暂以"各项目内部 SLA 独立"占位

### 6.3 客户代表 1 票否决权 SLA 未细化

- 客户代表（Ulysses 兼任）业务事项 1 票否决权 5 工作日（per 项目管理计划书 §12.2 CAB 6/7 多数 + 客户 1 票否决）
- 本模板 §2.2 仅占位"5 工作日"，未细化"业务事项边界 + 否决后回退路径"
- **建议**：Sprint 2 客户对接密度提升后单独定义

### 6.4 紧急档触发条件可能过严

- 8h 紧急档可能过于敏感（5 域 Lead 经常被多任务并行咨询）
- 启动会决议 4 通过方案 A 时未量化"紧急"判定标准
- **建议**：Sprint 1 W2 复盘时收集 R 角实际触发紧急档的次数，决定是否升 v1.0+1 放宽到 12h
