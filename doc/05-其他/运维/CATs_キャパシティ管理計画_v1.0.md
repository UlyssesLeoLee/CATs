## 3. 预测模型

### 3.1 数据源

| 源 | 频率 | 保留 |
|---|---|---|
| Prometheus | 15s 粒度 | 30 天本地，13 月远程 |
| Grafana 仪表盘快照 | 每日 | 永久 |
| 业务指标（任务量、TM 增长） | 每日 | 永久 |
| token-OLU 报告 | 每周 | 永久（per user 偏好） |

### 3.2 预测方法

| 周期 | 方法 | 输出 |
|------|------|------|
| **30 天** | 7 日移动平均 + 周环比 | 短期容量告警 |
| **60 天** | 线性回归 + 季节性（周/月） | 中期扩容计划 |
| **90 天** | Holt-Winters / Prophet | 季度评审输入 |

### 3.3 关键容量预测（示例）

| 资源 | 当前 | 30 天预测 | 60 天预测 | 90 天预测 | 行动 |
|------|------|-----------|-----------|-----------|------|
| TM 记录数 | 100K | 130K | 180K | 250K | 评估 pgvector 索引重建 |
| 月活客户 | 50 | 70 | 95 | 130 | 节点池评估 |
| PG 表大小 | 200 GB | 260 GB | 350 GB | 480 GB | 归档策略评审 |
| 月度 LLM token | 1B | 1.4B | 2B | 3B | 厂商配额谈判 |
| 月度并发 WS | 2000 | 2800 | 3800 | 5000 | collab-ws 副本评估 |

### 3.4 预测偏差监控

- 实际 vs 预测偏差 > 20% → 调整模型
- 实际 vs 预测偏差 > 50% → 启动容量根因复盘

## 4. 扩容流程

### 4.1 扩容决策树

```
指标达警戒
   │
   ├─ Pod 级别 → HPA（自动）
   │
   ├─ 节点池 → Cluster Autoscaler（自动，5~10 min）
   │
   └─ 集群容量 → 手动评审 + CAB 审批
```

### 4.2 自动扩容（HPA）

| 服务 | minReplicas | maxReplicas | 触发指标 |
|------|------------|-------------|----------|
| auth-service | 3 | 20 | CPU > 70% / RPS > 1500 |
| user-service | 3 | 15 | CPU > 70% |
| project-service | 3 | 15 | CPU > 70% |
| task-service | 3 | 12 | CPU > 70% + Kafka lag > 5000（KEDA）|
| file-service | 2 | 10 | CPU > 70% |
| llm-gateway | 3 | 15 | CPU > 70% + QPS > 200 |
| tm-service | 3 | 15 | CPU > 70% + QPS > 1000 |
| collab-ws | 5 | 20 | WS conn > 3000/副本 |
| 其余服务 | 2~3 | 5~10 | CPU > 70% |

> 自定义指标（Kafka lag / WS conn）需 Prometheus Adapter + KEDA（可热插拔 §5.2）。

### 4.3 PDB（PodDisruptionBudget）

所有服务 PDB ≥ 50% 最小可用，避免自愿中断期间雪崩。

### 4.4 节点池扩容

| 节点池 | 机型 | 数量 | 用途 |
|--------|------|------|------|
| system | 4C8G | 3 | K3s 控制面 + 系统组件 |
| app-general | 8C16G | 3~20 | 无状态应用（auto scale）|
| app-stateful | 8C32G | 3 | statefulset / 单副本 |
| gpu-llm（可选） | 16C64G + GPU | 2 | 本地 LLM |

### 4.5 手动扩容流程

1. **触发**：L2 预警 / 预测偏差 / 大客户接入
2. **评审**：SRE Lead + 架构师，30 min 内决策
3. **执行**：
   - 节点池：`cluster-autoscaler` 自动 / 手动 `kubectl scale`
   - 副本：`kubectl scale deploy/<svc> --replicas=N`
   - 存储：扩 PV / 加 broker / 扩 Redis 分片
4. **验证**：5 min 健康检查 + Grafana 指标回归
5. **记录**：扩容工单

## 5. 缩容注意事项

### 5.1 缩容原则

- 缩容 = 风险行为，必须 P2 变更
- 缩容前确保至少 7 天稳定低于 30% 利用率
- 缩容后保留 50% headroom（应对业务增长）
- 节假日 / 大客户活动前 7 天禁止缩容

### 5.2 缩容 Checklist

- [ ] 过去 7 天平均利用率 < 30%
- [ ] 预测模型显示 30 天内不会反弹
- [ ] PDB 不被违反（缩容后副本 ≥ PDB min）
- [ ] HPA 下限已相应调整
- [ ] 缩容后 24h 监控加强（每 2h 巡检）
- [ ] 回滚步骤就绪：`kubectl scale` + 节点池恢复

### 5.3 常见风险

| 风险 | 缓解 |
|------|------|
| HPA 抖动（缩容后马上又扩容）| 调整 stabilizationWindow |
| 缓存命中率下降 | 缩容前预热 |
| 长连接断开（Yjs WS） | drain + 强制迁移而非 kill |
| PG 连接池不足 | 缩容前评估 PgBouncer |
