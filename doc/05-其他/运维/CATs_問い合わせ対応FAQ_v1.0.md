## 1. 客户常见问题（客户成功一线）

### 1.1 登录 / 认证

| Q | A |
|---|---|
| Q1.1 忘记密码怎么办？ | 引导走 Keycloak 自助重置流程（ADR-005 §2.1）：登录页 → 忘记密码 → 邮箱链接 → 重置。如未收到邮件，① 检查垃圾邮件 ② 5 min 后重发 ③ 仍未收到则升级工单。 |
| Q1.2 启用了 MFA 但手机丢失？ | 引导用户使用 recovery code 登录（注册 MFA 时已生成 10 个一次性码）。recovery code 也丢失 → 客户支持手动重置 MFA（需企业管理员授权 + 身份核验）。 |
| Q1.3 SSO（OIDC / SAML）配置怎么接？ | 客户提供 IdP metadata + 回调 URL，引导企业管理员在控制台「企业设置 → SSO」按 Keycloak 流程配置（ADR-005 §2.1）。首次配置需 SRE 协助验证 issuer / 签名。 |
| Q1.4 多租户切换提示"无权限"？ | 检查用户在该租户的角色（ADR-005 §2.2 RBAC+ABAC）。如角色正确仍报错，截图 + tenant ID + 用户 ID 升级工单。 |

### 1.2 翻译质量

| Q | A |
|---|---|
| Q2.1 翻译结果不准确 / 不通顺？ | ① 检查 TM 召回：可能匹配到了低质量 TM 条目，引导标注 `tm.bad_match` 反馈 ② 检查术语表：缺失术语会导致误译，引导补全 ③ 如使用 LLM，可尝试切换模型 ④ 仍不达预期 → 走"质量反馈"工单。 |
| Q2.2 LLM 翻译超时？ | 检查 P99 延迟指标（运用手册 §1.4）。如平台侧问题 → 查 Status page → 升级 SRE。如仅客户项目问题 → 检查 prompt 长度 / context window。 |
| Q2.3 敏感内容被阻断？ | 架构设计书原则 3「合规 fail-closed」（ADR-005 §3）：敏感项目（`project.force_local_model=true`）调用云端 LLM 会被阻断。① 确认项目是否标记为敏感 ② 评估是否需要切换到本地模型 ③ 不允许绕过阻断。 |
| Q2.4 多模型投票结果差异大？ | 正常现象，差异大反映模型风格不同。引导用户在设置中选择主模型 + 投票权重。如有质量问题走 §1.2 流程。 |

### 1.3 TM 召回

| Q | A |
|---|---|
| Q3.1 TM 没有匹配到相似句子？ | ① 检查 TM 库是否包含该语种 ② 检查相似度阈值（默认 0.75）③ 检查是否启用了"上下文匹配" ④ 模糊匹配（P95 < 300ms）需 TM 库 > 1K 条；过小可能匹配不到。 |
| Q3.2 TM 匹配到的译文不准确？ | 用户可点 ❌ 标记为 bad_match，触发学习闭环。运营周维度看 bad_match 率 > 5% 触发 TM 评审。 |
| Q3.3 怎么导入 TMX / CSV？ | project-service 提供 TMX / CSV 导入（测试设计 §5.2 F11）。注意字段映射（`source` / `target` / `domain`），批量导入 > 10K 条走后台任务。 |
| Q3.4 pgvector 检索慢？ | ① 索引是否建立（`CREATE INDEX ... USING hnsw`）② TM 表行数 > 100K 需 ef_search 调优 ③ 升级 SRE 评估分区或独立向量库（ADR-003 §2）。 |

### 1.4 协同冲突

| Q | A |
|---|---|
| Q4.1 多人编辑同一段落，冲突怎么解决？ | Yjs CRDT 自动合并（ADR-002 §2 协同设计）。大多数情况无感合并；如字符级冲突按时间戳保留。客户端显示"合并历史"可回滚。 |
| Q4.2 协同中断 / 提示"离线"？ | 检查网络。如持续离线，① 本地 Yjs 自动保留离线编辑，重连后自动同步 ② 超过 24h 离线 → 客户端提示"快照保存"。如服务端异常 → Status page + 升级 SRE。 |
| Q4.3 我的修改没保存？ | ① 检查浏览器控制台错误 ② 检查是否在受邀编辑的角色内（ADR-005 RBAC）③ 历史版本可恢复（project-service 提供 versioned history）。 |

### 1.5 计费 / 订阅

| Q | A |
|---|---|
| Q5.1 当前订阅用量怎么看？ | 企业管理员在控制台「企业 → 用量」查看。billing-service 每日 02:00 出账。 |
| Q5.2 升级套餐？ | 控制台「企业 → 订阅 → 升级」自助操作，月度/年度切换按比例结算。 |
| Q5.3 计费有疑问 / 申请发票？ | 联系客户成功，附上企业 ID + 账单 ID + 异议项，3 工作日内回复。 |

### 1.6 性能问题

| Q | A |
|---|---|
| Q6.1 翻译速度慢？ | ① 客户端网络（自查）② 服务端延迟（Status page）③ TM 库大小（> 100K 模糊匹配可能慢）④ LLM 模型选择（本地 vs 云端）。常规 P95：L0 < 100ms / L1 < 300ms / L2 < 1s。 |
| Q6.2 浏览器卡顿？ | ① Chrome 扩展版本（最新）② 大文档（> 5K 段）建议分段 ③ 检查是否有大量 TM 浮窗（设置可关闭）。 |
| Q6.3 移动端能用吗？ | 移动端不在当前交付范围（可热插拔 §1.2）。建议桌面 Chrome / Edge / Firefox。 |

## 2. SRE 常见问题（值班 SRE）

### 2.1 部署失败

| Q | A |
|---|---|
| Q2.1 Argo CD 同步卡住？ | ① `argocd app get <name>` 看 diff ② 检查镜像是否在 Harbor 存在 ③ 检查 K8s 资源配额 ④ 必要时 `argocd app terminate-op` + 手动同步。详见 保守マニュアル §3。 |
| Q2.2 Pod 启动失败 / CrashLoopBackOff？ | ① `kubectl describe pod` 看 events ② `kubectl logs --previous` 看上次启动日志 ③ 常见原因：ConfigMap 缺失 / Secret 权限 / 镜像 tag 错 / 资源不足。 |
| Q2.3 数据库 migration 失败？ | ① 检查 `migration` 容器日志 ② 切回 Expand-Contract 上一步 ③ 用 `barman-cloud restore` 回滚 schema（运用手册 §3.2）。禁止手动改生产 schema。 |
| Q2.4 Canary 灰度失败需回滚？ | ① `argocd app rollback <name>` ② 或 `kubectl rollout undo` ③ 自动 abort 由 Argo Rollouts 触发（< 3 min）。详见 保守マニュアル §3.4。 |

### 2.2 性能下降

| Q | A |
|---|---|
| Q2.5 错误率突增？ | ① Grafana `cats-error-rate` 看板 ② 错误按 service / endpoint 分桶 ③ 看 Sentry / 日志关键词 ④ 按 インシデント対応プレイブック §4 走对应 runbook。 |
| Q2.6 延迟突增？ | ① 区分服务级 / 节点级 / 网络 ② 查 PG 慢日志（`pg_stat_statements`）③ 查 Kafka lag ④ 查下游 LLM 厂商状态。 |
| Q2.7 LLM 调用失败率高？ | ① 检查厂商状态（`api.openai.com/status`）② 切备选厂商（特性开关 `llm.provider`）③ 启用限流 + 队列。详见 インシデント対応プレイブック §4.3。 |
| Q2.8 Yjs WS 掉线率高？ | ① 查 collab-ws 日志 ② 节点网络（`ss -s`）③ 客户端版本分布（旧版本协议不兼容）。详见 インシデント対応プレイブック §4.4。 |

### 2.3 磁盘满

| Q | A |
|---|---|
| Q2.9 PG 磁盘满？ | ① 紧急：`VACUUM FULL` 释放 ② 长期：清理 archive WAL / 评估表分区 / 扩 PV ③ 切流到从库。详见 保守マニュアル §4 数据迁移。 |
| Q2.10 MinIO 磁盘满？ | ① 清理临时桶 `tmp-*` ② 归档老对象到冷存（mc ilm）③ 扩 PG cluster。 |
| Q2.11 节点磁盘满？ | ① `kubectl cordon` 节点 ② 清理 `kubelet` 日志 / 容器镜像 ③ 扩 PV / 加节点。 |

### 2.4 备份异常

| Q | A |
|---|---|
| Q2.12 barman 备份失败？ | ① `barman check cats-pg-prod` ② 检查网络到对象存储 ③ 检查 WAL 归档积压 ④ 必要时手动 `barman backup`。详见 运用マニュアル §3。 |
| Q2.13 需要 PITR 恢复？ | 严格按 运用マニュアル §3.2 流程，**不直接覆盖原集群**，先建副本验证。 |
| Q2.14 Kafka MirrorMaker 异常？ | ① 检查 MM2 connector 状态 ② 看 lag ③ 重启 connector ④ 评估网络。 |

### 2.5 Keycloak / 租户

| Q | A |
|---|---|
| Q2.15 用户登录全挂？ | P0：① Keycloak 集群状态 ② 切到备用 IdP（双活）③ DB 慢 / 锁 ④ 升架构师。详见 インシデント対応プレイブック §4。 |
| Q2.16 多租户隔离异常？ | ① 查 `pg_namespace.nspacl` ② 查 RLS 策略 ③ 关键数据导出 + 审计（ADR-005 §2.3）。**疑似数据泄漏 → 立即 P0 + 法律流程**。 |

## 4. 升级路径

### 4.1 客户问题升级

```
客户提单 → 1 线客服（< 1h 响应）
    │
    ├─ 已知 FAQ → 直接回复 + 关闭
    │
    ├─ 已知功能问题 → 升级产品 Lead（< 4h 响应）
    │
    ├─ 疑似平台故障 → 升级 SRE 当番（< 15 min 响应）
    │
    └─ 客户要求升级（VIP / SLA breach）→ CS Lead + 销售（< 30 min）
```

### 4.2 SRE 升级

```
值班 SRE（5 min 定位）
    │
    ├─ 已知 runbook → 执行 + 关闭
    │
    ├─ P1 事件 → 招集 SRE Lead（< 15 min）
    │
    ├─ P0 事件 → 招集 IC + 架构师 + CS（< 15 min）
    │
    └─ 架构级问题 → 升级架构师 + CTO（< 30 min）
```

### 4.3 跨部门

| 场景 | 路径 |
|------|------|
| 客户安全事件 | CS → SRE → 安全负责人 → 法律（ADR-005 §3）|
| 大客户 SLA 违约 | CS → SRE Lead → PMO → 销售 VP |
| 架构变更影响客户 | 架构师 → PMO → CS 提前 1 周通知 |
| 监管 / 媒体关注 | CS → PMO → CTO → 法务 |

### 4.4 升级 SLA 汇总

| 等级 | 客户响应 | SRE 响应 | 解决 SLA |
|------|----------|----------|----------|
| P0 | 5 min | 5 min | 1 h |
| P1 | 30 min | 15 min | 4 h |
| P2 | 1 工作日 | 1 h | 1 工作日 |
| P3 | 1 工作日 | 1 工作日 | 2 周 |
