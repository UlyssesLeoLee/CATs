## 1. 目的

定义 CATs 项目**从开发/测试环境到生产环境**的全部迁移要求，作为：

- 迁移设计（任务 40）的输入
- 迁移实施（任务 96-101）的依据
- F11 数据迁移功能的基线
- 上线窗口与回滚预案的基线

---

## 2. 范围

### 2.1 包含

| 类别 | 范围 |
|------|------|
| **数据迁移** | TM / 术语 / 项目 / 用户 / 配置 6 大域 |
| **系统切换** | 浏览器扩展升级 / 15 微服务部署 / 基础设施 |
| **环境升级** | Dev / Staging / Pre-prod / Prod |
| **回滚** | 任意步骤 5 分钟内可回滚 |
| **演练** | 至少 1 次完整预演 |

### 2.2 不包含

- 历史数据清洗（项目周期内）
- 旧 CAT 系统的退役（独立项目）
- 跨地域灾备切换（v2.0）

## 4. 迁移策略

### 4.1 总体策略

**滚动迁移 + Canary 切流**

| 阶段 | 内容 | 持续 |
|------|------|------|
| 1. 准备 | 目标环境就绪 | T-7d ~ T-1d |
| 2. 数据迁移（首次） | 全量 ETL | T-1d |
| 3. 演练 | Staging 全流程 | T-1w（演练周） |
| 4. 切流 5% | Canary | T-0 00:00 |
| 5. 切流 25% | 扩大 | T-0 06:00 |
| 6. 切流 50% | 扩大 | T-0 12:00 |
| 7. 切流 100% | 完成 | T-0 18:00 |
| 8. 旧系统保留 | 7 天只读 | T+0 ~ T+7d |
| 9. 旧系统退役 | 关闭 | T+7d |

> T-0 = 上线日 2027-10-01 02:00（暂定）

### 4.2 数据迁移策略

| 域 | 策略 | 一致性 | 回滚 |
|----|------|--------|------|
| TM | 全量 + 增量 + Outbox | 最终一致 | 全量回退（双写期） |
| 术语 | 全量 + 增量 | 最终一致 | 同上 |
| 项目 | 全量 + 增量 | 最终一致 | 同上 |
| 用户 | 全量 | 强一致 | 全量回退 |
| 审计 | 全新 | N/A | N/A |
| 配置 | 全新 | N/A | N/A |
| 文件 | 全量 + 增量校验 | 强一致 | 全量回退 |
| 媒体 | 全量 + 增量校验 | 强一致 | 全量回退 |

### 4.3 双写期

- 切换前 2 周：旧系统 → 新系统（单向同步）
- 切换前 1 周：双写（冲突解决以新系统为准）
- 切换后 1 周：新系统 → 旧系统（只读）
- 切换后 2 周：退役旧系统

## 5. 切流策略

### 5.1 DNS / 网关

| 阶段 | 浏览器 | API | 状态 |
|------|--------|-----|------|
| T-7d | 旧 | 旧 | 准备 |
| T-0 00:00 | 5% 新 | 5% 新 | Canary |
| T-0 06:00 | 25% 新 | 25% 新 | 扩大 |
| T-0 12:00 | 50% 新 | 50% 新 | 扩大 |
| T-0 18:00 | 100% 新 | 100% 新 | 完成 |
| T+7d | 退役旧 | 退役旧 | 收尾 |

### 5.2 切流观察指标

| 指标 | 阈值 | 行动 |
|------|------|------|
| 错误率 | > 1% | 暂停切流 |
| 响应时间 P95 | > 2s | 暂停切流 |
| CPU / 内存 | > 85% | 扩容 |
| DB 连接 | > 80% | 扩容 |
| 队列积压 | > 1000 | 告警 |
| 审计异常 | > 0 | 立即告警 |

### 5.3 回滚

- 任意阶段可回滚（5 分钟内）
- 回滚命令：`kubectl rollout undo` + DNS 回切
- 数据回滚：双写期保证
