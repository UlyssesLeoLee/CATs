# CATs 项目文档目录

**全媒体 AI 辅助翻译 SaaS 平台 —— 设计与工程文档库**

本项目文档库覆盖需求定义、微服务基础设计、各模块详细设计、测试策略设计、可热插拔运维部署及工程管理工作流。

---

## 1. 目录结构全景

```
doc/
├── 01-需求/                          # 需求输入与规格说明
│   ├── 原始需求/                      # 初版构想与背景调研
│   └── 需求规格说明/                   # 需求规格说明书与需求定义书（OFCAT 基线）
│
├── 02-基础设计/                      # 架构设计与技术选型
│   ├── 架构设计/                      # CATs 微服务架构、可热插拔部署与运维、转型命名说明、（OFCAT 历史基线）
│   └── 技术选型/                      # CATs 技术选型 v2.0、Rust 生态深度选型 v1.0、（OFCAT 历史基线）
│
├── 03-详细设计/                      # 核心模块、接口契约与数据模型
│   ├── 模块设计/                      # 微服务内部分层/管线设计、游戏本地化模块设计
│   ├── 接口设计/                      # 微服务 REST / gRPC / Kafka 事件契约
│   └── 数据库设计/                     # PostgreSQL 8 逻辑库 DDL、索引、CDC 对应关系
│
├── 04-测试/                          # 测试策略与设计
│   └── 测试设计书/                    # JIS X 0129 / ISO 29119 标准测试设计书与测试矩阵
│
└── 05-其他/                          # 工程管理、质量控制与评审
    ├── CATs_实施前QA登记册_v1.0.md    # Pre-mortem 实施前 50+ 关心事项与阻塞项登记
    ├── CATs_工作流文档_v1.0.md        # 基于日本式 150 任务标准的工程进度对齐
    └── 评审记录/                      # 设计评审会议记录与决策归档
```

## 4. 文档编写与维护约定

1. **格式规范**：正文使用 Markdown 编写，表格、列表严格对齐；如需可筛选数据，由 `_build/build_*.py` 脚本统一生成配套 `.xlsx` 工作簿。
2. **图表规范**：推荐使用 Mermaid 代码块内嵌流程图、时序图与状态机。
3. **元数据要求**：每篇正式文档顶部必须包含标准元数据表格（文档编号、文档名、版本、创建日、作者、状态、密级、上游/下游文档、修订履历、审批栏）。
