## 一句话定位

浏览器插件 + 本地术语库 + AI 翻译 + PDF/网页翻译 + CAT 工作流,
即「AI 增强型 CAT 浏览器工作台」。

## 体验目标

把传统 CAT 的「复制/粘贴/导入/导出/上传/下载」多步流程,压缩成
「看到 → 选中 → 翻译 → 确认 → 结束」两步操作。

## 初版功能清单

1. 网页直接翻译(选中 → 右键 AI Translate → 术语匹配 + 建议译文 → 回车写入)
2. 翻译记忆库 TM(100% / 模糊匹配自动填充)
3. 术语库优先(术语强制统一,Prompt 自动注入)
4. 网页 PDF 翻译(pdf.js 提取文字/表格/OCR,左右双语对照,滚动同步)
5. 截图翻译(框选 → OCR → 术语匹配 → AI 翻译)
6. Jira 模式(识别标题/描述/评论/附件,翻译/总结/提炼需求/生成标签)
7. 语义污染防护(先做领域识别,再术语注入,再翻译,再 QA)
8. 多模型投票(GPT/Claude/Gemini 并行 + Judge LLM 评审取最优)
9. 本地术语库(SQLite,表:terms / translation_memory / projects / history)
10. 无限上下文(文档级实体记忆:角色名/地名/组织名/专有词,后文统一)

## 初版技术设想

- 前端:Chrome Extension + React + TypeScript
- CAT 核心:LangGraph(OCR/TM/Term/Translate/QA 多 Agent)
- 存储:SQLite + Qdrant
- 模型:OpenAI / Claude / Gemini / DeepSeek / 本地 Qwen
- PDF:pdf.js
- OCR:PaddleOCR

## 架构师初评要点(已在需求沟通中纳入)

- 纯扩展跑不动 SQLite/PaddleOCR/LangGraph/本地 LLM → 改为「薄扩展 + 本地引擎」。
- "极简体验"与"多模型投票/QA 重管线"在延迟上冲突 → 分层延迟策略。
- 术语"强制"靠 Prompt 不可靠 → 增加译后强制校验/替换。
- 标签/占位符保护是真正护城河 → 提前进 MVP。
- 数据合规(Jira/邮件上云)是能否在公司使用的前提 → AI Gateway 做合规开关。
