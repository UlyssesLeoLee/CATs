## 1. 项目背景与目标

OFCAT 是一款面向**内部本地化/反馈处理团队**的「AI 增强型 CAT 浏览器工作台」。
目标是把传统 CAT(Trados/memoQ)的多步流程压缩为「看到 → 选中 → 翻译 → 确认」
的近乎两步操作,同时保留 CAT 的核心确定性能力(翻译记忆、术语统一、QA、标签保护),
并融合 AI 翻译与多语种支持。

**成功标准(初定):**
- 网页选区翻译的单次操作链 ≤ 2 个显式动作(选中 + 确认)。
- 常见句段(TM 命中)翻译为"即时、不调用云端 API"。
- 术语库命中项的译文 100% 符合规定术语(可强制校验)。
- 敏感内容可在不出本地的前提下完成翻译。

## 2. 已锁定的架构约束(需求级,不可违背)

> 这些来自需求沟通的拍板结论,作为所有后续设计的硬约束。

| 约束 | 结论 |
|---|---|
| C1 部署形态 | **薄扩展 + 本地伴随引擎**。扩展只做选区捕获/UI/快捷键;CAT 引擎(TM/术语/QA/编排/OCR/本地 LLM)放本地服务,经 `127.0.0.1` 或 Native Messaging 通信。 |
| C2 定位 | 团队内部工具。重稳定与可维护性,**不做**账号体系、计费、对外多租户。 |
| C3 数据合规 | AI Gateway 必须支持**模型路由 + 合规开关**:可按域名/项目把敏感内容强制路由到本地模型,云端/本地走统一(OpenAI 兼容)协议。 |
| C4 数据归属 | TM/术语库**本地为主 + 可选同步**:本地 SQLite 为权威副本保证离线快速;另设轻量中心同步服务,同步术语库与核心 TM(非实时协作)。 |
| C5 多语种 | TM/术语条目的主键必须包含 `源语言 → 目标语言` 维度,不得写死中/日/英。 |
| C6 存量数据 | 存量 TM/术语格式杂乱,需要"清洗 + 字段映射 + 导入"管道,不能假设标准 TMX/TBX。 |

## 3. 范围(Scope)

### 3.1 MVP(第一版,必须交付)
**场景:网页选区翻译闭环。** 打通如下链路:

```
选区捕获 → TM/术语匹配 → 标签/占位符保护 → 单模型流式翻译
        → 行内 overlay 展示(术语提示+建议译文) → 确认/编辑 → 写回页面 + 回存 TM
```

### 3.2 后续迭代(已规划,非 MVP)
- PDF 双语对照翻译(pdf.js + 版面对齐)
- Jira 反馈模式(识别字段 + 翻译/总结/标签生成)
- 截图 / 图片 OCR 翻译(PaddleOCR)
- 多模型投票 + Judge 评审(高质量模式)
- 本地 LLM 接入(合规路径)
- 文档级实体记忆(角色名/地名/专有词统一)

### 3.3 不做(Out of Scope)
- 用户账号体系、付费/订阅、对外多租户 SaaS。
- 实时多人协同编辑同一文档(同步为异步拉取,非实时锁)。
- 移动端。

## 4. 用户与典型场景

- **主要用户**:内部本地化译员 / 反馈处理人员(处理网页内容、Jira 反馈、规格文档、游戏文本)。
- **典型工作流(MVP)**:在浏览器中阅读外语网页 → 选中一段文本 → 触发翻译 →
  系统显示 TM/术语匹配与建议译文 → 译员确认或微调 → 译文写回并沉淀进 TM。

## 5. 功能需求(MVP 细化)

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F1 | 选区捕获 | 选中网页文本,通过快捷键/右键/浮动按钮触发翻译。 | 必须 |
| F2 | TM 匹配 | 精确(100%)与模糊(编辑距离/相似度为主)匹配;命中模糊匹配高亮差异。 | 必须 |
| F3 | 术语匹配与注入 | 命中术语在 overlay 中提示;术语作为约束注入翻译请求。 | 必须 |
| F4 | 术语强制校验 | 译后扫描:规定术语未按用法出现则标红/可一键替换(不靠模型自觉)。 | 必须 |
| F5 | 标签/占位符保护 | `<b>`、`{count}`、`%s`、`{{name}}` 等翻译前替换为哨兵、译后回填并校验数量一致。 | 必须 |
| F6 | 单模型流式翻译 | 默认走单模型流式输出,~1s 内见首字。 | 必须 |
| F7 | 行内 overlay 编辑 | 原文旁显示译文,可编辑;回车确认。 | 必须 |
| F8 | 写回页面 | 将确认译文写回选区;对富文本编辑器(ProseMirror/CodeMirror)走安全写入,不破坏文档。 | 必须 |
| F9 | 回存 TM | 确认后的译文以 `源语言→目标语言` 维度沉淀进本地 TM。 | 必须 |
| F10 | 合规路由 | 按域名/项目把请求路由到云端或本地模型。 | 必须 |
| F11 | 存量导入 | 支持把杂乱的存量术语/TM(Excel/CSV/TMX/TBX)经清洗映射导入。 | 高 |

## 6. 非功能需求

- **延迟分层**:L0 TM 100% 命中即时且不调 API;L1 模糊命中即时回填待确认;
  L2(默认)单模型流式 ~1s 见首字;L3(手动)多模型投票 5–10s。
- **合规**:敏感域名/项目内容不得发往云端;合规开关默认值可配置。
- **离线可用**:TM/术语匹配、本地模型路径在断网时仍可用。
- **可维护性**:扩展与本地引擎职责清晰、接口契约稳定;引擎可独立升级。
- **数据安全**:本地 SQLite 可备份/迁移;同步通道加密。

## 7. 数据需求

- 存储:本地 SQLite(权威副本),表初定 `terms / translation_memory / projects / history`,
  TM/术语条目带 `source_lang / target_lang / domain(领域)` 维度(满足 C5)。
- 同步:轻量中心服务同步术语库与核心 TM(满足 C4,异步拉取)。
- 导入:清洗 + 字段映射 + 去重管道(满足 C6)。

## 8. 模型与 AI Gateway 需求

- 统一走 **OpenAI 兼容协议**,云端(OpenAI/Claude/Gemini/DeepSeek)与本地模型同一接口。
- 合规开关只切换 `base_url` / 模型路由,不改调用方逻辑。
- **本地模型建议(待技术选型确认)**:Qwen 系列(中日英强、指令遵循好),
  单机用 Ollama、团队共享 GPU 用 vLLM。完整对比见 `02-基础设计/技术选型/`。

## 9. 待确认问题(Open Issues)

|---|---|---|
| O1 | 团队规模与日均翻译量级、TM 预期条数级别? | 影响 TM 索引方案与同步服务规格 |

| O6 | "敏感"如何界定(按域名清单 / 按项目标记)? | 影响合规开关默认策略(F10) |

## 10. 里程碑(初定)

1. **M1 — MVP 闭环**:F1–F10 打通(网页选区翻译可用)。
2. **M2 — 数据底座**:F11 存量导入 + 本地/同步数据层完善。
3. **M3 — 文档场景**:PDF 双语对照。
4. **M4 — 工作流场景**:Jira 模式。
5. **M5 — 增强能力**:OCR、多模型投票、本地 LLM、文档级实体记忆。
