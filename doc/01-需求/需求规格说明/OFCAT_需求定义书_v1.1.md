## 1. 前言

### 1.1 本文档目的
本文档定义 OFCAT 的**需求**，用于在关系者之间达成共识，并作为基础设计（`02-基础设计/`）、详细设计（`03-详细设计/`）的输入。

### 1.2 目标读者
项目关系者、开发负责人、本地化/反馈处理团队（终端用户代表）、评审批准人。

### 1.3 适用范围
本文档涵盖 OFCAT 的**整体需求**，但功能的详细规格（F1–F11）以**第一版（MVP：网页选区翻译）**为主对象，后续功能仅在概要层面定义（见 3.5 节）。

### 1.4 术语定义

| 术语 | 英文/全称 | 定义 |
|---|---|---|
| CAT | Computer-Assisted Translation | 计算机辅助翻译。译员主导、工具辅助的翻译作业方式。 |
| TM | Translation Memory（翻译记忆库） | 翻译记忆库。已确认的原文-译文对的复用库。 |
| 术语库 | Termbase | 规定特定术语在特定领域的统一译法。 |
| 句段 | Segment | 翻译作业的最小单位（通常为一句）。 |
| 模糊匹配 | Fuzzy Match | TM 中与当前原文相似但非完全一致的命中（以相似度 % 表示）。 |
| 精确匹配 | 100% Match | TM 中与当前原文完全一致的命中。 |
| 占位符 | Placeholder | `{count}`、`%s`、`{{name}}` 等需原样保留的可变标记。 |
| 标签保护 | Tag Protection | 翻译过程中保护 HTML/标记标签不被破坏的机制。 |
| 薄扩展 | Thin Extension | 仅承担 UI/捕获、不含重逻辑的浏览器扩展。 |
| 本地引擎 | Local Engine | 本机运行的 CAT 核心服务（TM/术语/QA/编排/OCR/本地 LLM）。 |
| AI 网关 | AI Gateway | 统一封装云端/本地各 LLM、负责模型路由与合规开关的组件。 |
| 合规开关 | Compliance Switch | 按域名/项目把敏感内容强制路由到本地模型的机制。 |

## 2. 系统概要

### 2.1 背景
传统 CAT 工具（Trados Studio、memoQ）的作业流程包含「复制/粘贴/导入/导出/上传/下载」过多步骤，效率低。内部本地化/反馈处理团队需要一种在浏览器内即可完成、操作极简、且保留 CAT 确定性能力（TM/术语/QA/标签保护）的翻译作业工具。

### 2.2 现状课题

| 编号 | 课题 |
|---|---|
| 课题1 | 现有 CAT 工具操作步骤多，网页/Jira/PDF 内容需反复导入导出。 |
| 课题2 | 通用网页翻译插件不具备 TM、术语统一、标签保护等 CAT 能力。 |
| 课题3 | 纯 AI 翻译术语不统一、易受领域语义污染（如游戏文本误判为客户反馈）。 |
| 课题4 | 敏感内容（Jira/邮件）直接上云存在合规风险，无法在公司使用。 |
| 课题5 | 存量术语/TM 数据格式杂乱，难以复用。 |

### 2.3 系统化目的
在浏览器内提供「看到 → 选中 → 翻译 → 确认」近乎两步的极简翻译作业体验，同时融合 TM 复用、术语强制统一、标签保护、QA 与多语种 AI 翻译，并满足数据合规。

### 2.4 期望效果（KPI 候选）

| 编号 | 指标 | 目标值 |
|---|---|---|
| 效果1 | 网页选区翻译的显式操作数 | ≤ 2（选中 + 确认） |
| 效果2 | TM 精确匹配句段的响应 | 即时，且**不调用云端 API** |
| 效果3 | 术语库命中项的译文术语符合率 | 100%（可强制校验） |
| 效果4 | 敏感内容上云率 | 0%（强制本地路由） |
| 效果5 | 综合作业效率（对比传统 CAT） | 3〜10 倍（目标值，需实测验证） |

### 2.5 系统化范围
见 3.5 节「对象范围」。

## 3. 前提条件与约束条件

### 3.1 已确定约束（架构约束）

> 需求沟通中已达成共识的硬约束。后续设计不得逸脱。

| ID | 约束名 | 内容 |
|---|---|---|
| C1 | 部署形态 | **薄扩展 + 本地引擎**。扩展仅做选区捕获/UI/快捷键；CAT 引擎放本机服务，经 `127.0.0.1` 或 Native Messaging 通信。 |
| C2 | 产品定位 | 社内工具。重稳定与可维护性，**不做**账号体系、计费、对外多租户。 |
| C3 | 数据合规 | AI 网关必须支持**模型路由 + 合规开关**：按域名/项目把敏感内容强制路由到本地模型；云端/本地统一为 OpenAI 兼容协议。 |
| C4 | 数据归属 | TM/术语库**本地为主 + 可选同步**：本机 SQLite 为权威副本（保证离线/快速）；另设轻量中心同步服务，同步术语库与核心 TM（**非实时协作**）。 |
| C5 | 多语种 | TM/术语条目主键必须含 `源语言 → 目标语言` 维度，不得写死中/日/英。 |
| C6 | 迁移数据 | 存量 TM/术语格式杂乱，需要「清洗 + 字段映射 + 去重」导入管道，不可假设标准 TMX/TBX。 |

### 3.2 前提条件
- 用户 PC 可安装本地引擎（伴随程序）。
- 浏览器为 Chromium 系（以 Edge 为主，是否含 Chrome 见课题 O2）。

### 3.3 假定环境

| 区分 | 内容 |
|---|---|
| 客户端 | Chromium 系浏览器（Edge 主）+ 本地引擎（localhost 服务 / 桌面端） |
| 服务端 | 轻量中心同步服务（同步术语库/核心 TM，内网或云） |
| 模型 | 云端（OpenAI/Claude/Gemini/DeepSeek）+ 本地 LLM（Qwen 系，推荐 Ollama/vLLM） |

### 3.4 约束事项（补充）
- 富文本编辑器（ProseMirror/CodeMirror 等）的写回须经其 API/模拟输入，禁止直接改写 `innerText`（防止文档破坏）。
- MV3 service worker 不适合长时间任务，故重处理放本地引擎侧（与 C1 一致）。

### 3.5 对象范围

#### 3.5.1 第一版（MVP / 对象）
**网页选区翻译闭环。** 功能 F1–F11（第 5 章）。

#### 3.5.2 后续阶段（已规划）
PDF 双语对照、Jira 反馈模式、截图/OCR、多模型投票、本地 LLM 接入、文档级实体记忆。

#### 3.5.3 对象外（Out of Scope）
账号体系、计费、对外多租户 SaaS、实时多人协同编辑、移动端。

## 4. 业务需求

### 4.1 干系人

| 区分 | 角色 | 关注点 |
|---|---|---|
| 终端用户 | 本地化译员 / 反馈处理人员 | 操作极简、术语统一、质量稳定 |
| 管理者 | 术语库/TM 维护者 | 术语一致性、存量数据导入、同步 |
| 运维 | 中心同步服务、本地模型运维 | 可用性、合规、安全 |

### 4.2 用户特性
日常处理多语种内容（网页、Jira 反馈、规格文档、游戏文本），熟悉 CAT 概念，期望减少机械操作步骤。

### 4.3 使用场景（MVP）
译员在浏览器中阅读外语网页 → 选中文本段 → 触发翻译 → 系统显示 TM/术语匹配与建议译文 → 确认或微调 → 译文写回页面并沉淀进 TM。

### 4.4 业务流程（MVP 主流程）

```
[选择原文]
   │
   ▼
[TM 匹配] ──精确匹配(L0)──▶ [即时填充·不调用 API]──┐
   │                                                │
   │──模糊匹配(L1)──▶ [差异高亮·等待确认]──────────┤
   │                                                │
   └──未命中──▶ [术语匹配]──▶[标签/占位符保护]       │
                    │                               │
                    ▼                               │
            [单模型流式翻译(L2)]                      │
                    │                               │
                    ▼                               │
            [术语强制校验(F4)]                        │
                    │                               │
                    ▼                               │
       [行内 overlay 展示·编辑]◀────────────────────┘
                    │
                    ▼ (确认/回车)
            [写回页面(F8)]
                    │
                    ▼
            [保存进 TM(F9)]
```

### 5.2 功能规格（功能明细卡）

> 颗粒度：每个功能给出 触发/输入/处理/输出/业务规则/例外 的明细。

#### F1 选区捕获
| 项目 | 内容 |
|---|---|
| 功能ID | F1 |
| 概要 | 获取用户在网页上选中的文本作为翻译对象。 |
| 触发 | ①快捷键；②右键菜单「AI Translate」；③选区旁浮动按钮。 |
| 输入 | 选中文本、所在 DOM 节点、页面 URL/域名、（可能的）语言信息。 |
| 处理 | 获取选区文本与上下文；识别源语言；判定域名是否敏感（供 F10）。 |
| 输出 | 标准化句段（原文 + 元信息）。 |
| 业务规则 | 空选区/纯符号不触发；过长选区按句段切分。 |
| 例外/错误 | 不可编辑区域、跨 iframe 选区、富文本节点 → 标记为「需特殊写回」（关联 F8）。 |
| 关联功能 | F2, F8, F10 |

#### F2 TM 匹配
| 项目 | 内容 |
|---|---|
| 功能ID | F2 |
| 概要 | 将句段与 TM 匹配，返回精确匹配/模糊匹配。 |
| 输入 | 句段原文、源语言、目标语言、（可选）领域/项目。 |
| 处理 | ①精确匹配检索；②模糊匹配（**以编辑距离/token 相似度为主**、语义向量为辅）。计算相似度 %。 |
| 输出 | 命中候选（译文、相似度 %、来源）。精确匹配为 L0，模糊为 L1。 |
| 业务规则 | 精确匹配（100%）不调用 API、即时填充。模糊（默认 85% 以上）高亮差异、等待确认。 |
| 例外/错误 | TM 未初始化/为空 → 视为未命中，转 L2。 |
| 关联功能 | F6, F9 |

#### F3 术语匹配与注入
| 项目 | 内容 |
|---|---|
| 功能ID | F3 |
| 概要 | 将句段内术语与术语库匹配，提示约定译法并注入翻译请求。 |
| 输入 | 句段原文、源/目标语言、领域。 |
| 处理 | 术语抽取 → 术语库匹配 → 在 overlay 中提示，并作为约束注入翻译提示词。 |
| 输出 | 命中术语列表（原词/约定译法/领域）。 |
| 业务规则 | 按多语种维度（C5）匹配。领域有不同译法时以领域设定优先。 |
| 例外/错误 | 术语库未设定 → 不注入，继续翻译。 |
| 关联功能 | F4, F6 |

#### F4 术语强制校验
| 项目 | 内容 |
|---|---|
| 功能ID | F4 |
| 概要 | 校验翻译结果是否遵循术语库的约定译法，对未遵循项标示/替换。 |
| 输入 | 翻译结果、F3 命中术语列表。 |
| 处理 | 扫描译文，检出未使用约定译法的术语。标红显示并提供一键替换。 |
| 输出 | 违反列表 + 修正候选。 |
| 业务规则 | 不依赖模型自觉（仅提示词注入不作保证），确保确定性。 |
| 例外/错误 | 上下文不可替换时仅警告（不自动替换）。 |
| 关联功能 | F3, F7 |

#### F5 标签/占位符保护
| 项目 | 内容 |
|---|---|
| 功能ID | F5 |
| 概要 | 翻译中不破坏 `<b>`、`{count}`、`%s`、`{{name}}` 等。 |
| 输入 | 原文（含标签/占位符）。 |
| 处理 | 翻译前替换为哨兵 token → 翻译 → 译后回填 → 校验数量与完整性。 |
| 输出 | 标签/占位符保全的译文。 |
| 业务规则 | 数量不一致视为 QA 错误（F7 警告）。位置可移动，欠缺/增加不可。 |
| 例外/错误 | 无法回填（数量不一致）→ 向用户警告并要求确认。 |
| 关联功能 | F6, F7 |

#### F6 单模型流式翻译
| 项目 | 内容 |
|---|---|
| 功能ID | F6 |
| 概要 | 作为默认路径，使用单模型进行流式翻译（L2）。 |
| 输入 | 受保护句段、术语约束（F3）、源/目标语言、领域。 |
| 处理 | 经 AI 网关向模型请求；流式输出；~1s 内显示首字。 |
| 输出 | 译文（流式）。 |
| 业务规则 | 默认为单模型。多模型投票（L3）为手动触发的独立功能（后续）。 |
| 例外/错误 | 模型响应失败 → 重试/回退到备用模型（可配置）。 |
| 关联功能 | F3, F5, F10 |

#### F7 行内 overlay 编辑
| 项目 | 内容 |
|---|---|
| 功能ID | F7 |
| 概要 | 在原文附近展示译文，可编辑、确认。 |
| 输入 | 译文、术语提示、QA 警告（F4/F5）。 |
| 处理 | overlay 展示；高亮术语命中/QA 违反；可编辑；回车确认。 |
| 输出 | 确认译文。 |
| 业务规则 | 可仅用键盘完成操作（操作数最小化，效果1）。 |
| 例外/错误 | 用户取消 → 不写回/不保存。 |
| 关联功能 | F4, F5, F8 |

#### F8 写回页面
| 项目 | 内容 |
|---|---|
| 功能ID | F8 |
| 概要 | 将确认译文写回选区。 |
| 输入 | 确认译文、目标 DOM 节点类型。 |
| 处理 | 普通文本直接替换；富文本编辑器（ProseMirror/CodeMirror）经其 API/模拟输入安全写入。 |
| 输出 | 更新后的页面。 |
| 业务规则 | 禁止直接改写 `innerText`（防止文档破坏）。 |
| 例外/错误 | 不可写入区域 → 仅提供译文供复制。 |
| 关联功能 | F1, F7 |

#### F9 保存进 TM
| 项目 | 内容 |
|---|---|
| 功能ID | F9 |
| 概要 | 将确认译文沉淀进 TM。 |
| 输入 | 原文、确认译文、源/目标语言、领域、项目。 |
| 处理 | 按 `源语言→目标语言` 维度（C5）保存进本机 SQLite TM；重复则更新。 |
| 输出 | 更新后的 TM。 |
| 业务规则 | 同步对象的核心 TM 推送至中心服务（C4，非实时）。 |
| 例外/错误 | 保存失败 → 本地队列重试。 |
| 关联功能 | F2, F11 |

#### F10 合规路由
| 项目 | 内容 |
|---|---|
| 功能ID | F10 |
| 概要 | 按域名/项目将请求路由到云端/本地模型。 |
| 输入 | 域名/项目、敏感判定、模型设定。 |
| 处理 | 敏感为真 → 强制路由到本地模型；否则 → 默认（可云端）。云端/本地以 OpenAI 兼容协议统一，仅切换 `base_url`。 |
| 输出 | 选定的模型端点。 |
| 业务规则 | 敏感内容上云率 0%（效果4）。默认策略可配置（课题 O6）。 |
| 例外/错误 | 本地模型不可达 → 中止翻译并警告（不把敏感内容流向云端）。 |
| 关联功能 | F6 |

#### F11 存量数据导入
| 项目 | 内容 |
|---|---|
| 功能ID | F11 |
| 概要 | 将杂乱的存量术语/TM 经清洗、映射后导入。 |
| 输入 | Excel/CSV/TMX/TBX 等（格式不统一）。 |
| 处理 | 清洗 → 字段映射（源/目标/领域）→ 去重 → 导入本机 SQLite。 |
| 输出 | 导入结果报告（成功/重复/错误条数）。 |
| 业务规则 | 不以标准 TMX/TBX 为前提（C6）。映射定义须经用户确认。 |
| 例外/错误 | 非法行跳过并记入报告。 |
| 关联功能 | F2, F9 |

## 6. 非功能需求

> 按 IPA「非功能需求等级」标准的分类定义。

### 6.1 可用性
- 本地功能（TM/术语匹配、本地模型路径）在离线时仍可用。
- 中心同步服务停止时本地作业仍可继续（C4）。

### 6.2 性能与扩展性
- **延迟分层：**

| 层级 | 条件 | 目标延迟 | 路径 |
|---|---|---|---|
| L0 | TM 精确匹配 | 即时·不调用 API | 直接填充 |
| L1 | TM 模糊匹配 | 即时 | 填充+等待确认 |
| L2（默认） | TM 未命中 | ~1s 显示首字（流式） | 单模型+术语注入+QA |
| L3（手动） | 用户指定 | 5〜10s | 多模型投票+评审 |

- TM 条数的预想规模在课题 O1 确定后，再确定索引方式。

### 6.3 运维与可维护性
- 薄扩展与本地引擎职责分离，引擎可独立升级。
- 稳定扩展↔引擎、AI 网关的接口契约。

### 6.4 迁移性
- 提供存量术语/TM 的导入管道（F11）。
- 本机 SQLite 可备份/迁移。

### 6.5 安全与合规
- 敏感域名/项目内容不发往云端（C3、F10、效果4）。
- 同步通道加密；本地数据本地保管。

### 6.6 系统环境
- 客户端：Chromium 系浏览器 + 本地引擎。
- 模型：云端 + 本地 LLM（推荐 Qwen 系、Ollama/vLLM）。

## 7. 系统构成（概要）

```
┌──────────────────────────┐
│ 薄扩展（Thin Extension）   │  选区捕获 / overlay UI / 快捷键 / 截图抓取
└────────────┬─────────────┘
             │ 127.0.0.1 / Native Messaging
┌────────────▼─────────────┐
│ 本地引擎（Local Engine）   │  TM / 术语 / QA / 编排 / (后续)OCR·本地 LLM
│  └ SQLite（本地权威副本）  │
└────────────┬─────────────┘
             │                         ┌──────────────────┐
             ├────────同步(可选)───────▶│ 中心同步服务       │ 术语/核心 TM
             │                         └──────────────────┘
┌────────────▼─────────────┐
│ AI 网关                   │  模型路由 + 合规开关
│  云端: OpenAI/Claude/...   │  本地: Qwen(Ollama/vLLM)
└──────────────────────────┘
```

详细在基础设计书（`02-基础设计/架构设计/`）中定义。

---

## 8. 数据需求（概要）

- 以本机 SQLite 为权威副本。表初案：`terms` / `translation_memory` / `projects` / `history`。
- TM/术语条目必须含 `source_lang` / `target_lang` / `domain（领域）` 维度（C5）。
- 中心同步对象为术语库与核心 TM（C4，非实时）。
- 详细 schema 在 `03-详细设计/数据库设计/` 中定义。

---

## 9. 外部接口需求（概要）

- 云端/本地模型以 **OpenAI 兼容协议**统一。
- 合规开关仅通过切换 `base_url`/模型路由实现，不改变调用方逻辑。
- 本地模型推荐：Qwen 系（中日英强、指令遵循好）。单机用 Ollama，共享 GPU 用 vLLM。**详细对比在技术选型书中确定。**
