feat(services): 接线 4 个 crate，约 1450 行从「写在磁盘上」变成「真的在编译」

上一轮实证出 12 个 crate 共 5731 行 .rs 从未被编译。拍板后接 translation-core
与 worker-service，实战中发现真正的根因比预想深一层：那 170 行依赖的 API
**根本不存在**，而同样的病长在共享 crate 上。

## 根因：共享错误体系从未被打开

`common/src/error.rs`（550 行的 ErrorCode / CatsError / Result / ErrorBody
+ HTTP/gRPC 映射）没有 `pub mod error;`，所以 `cats_common::CatsError`
在整个仓库里是不可用的。

后果不是「少了个模块」，而是**全仓错误模型分裂**：
凡是用 `use cats_common::{CatsError, ErrorCode}` 的文件
（audit/file/notification 的 db.rs·handlers.rs·consumer.rs、
translation-core 的 service.rs·db.rs·ai_gateway.rs、
cats-rbac 的 service_helpers.rs、worker-service 的 scheduler.rs）
**全部都在未编译的模块里**；而真正在编译的 7 个服务
各自内联了一套错误处理，没有共享类型。

`cats-rbac/src/service_helpers.rs`（178 行）是同一个病。

## 接线过程中暴露的真实编译错误（9 → 1 → 0 三轮）

**1. prost 会把 proto3 类型名规范化 —— 这段代码照着 .proto 里的名字写，
   不是照着 prost 生成的名字写：**

  TMMatchItem      -> TmMatchItem
  MatchTMRequest   -> MatchTmRequest
  MatchTMResponse  -> MatchTmResponse
  QAViolation      -> QaViolation
  RunQARequest     -> RunQaRequest
  RunQAResponse    -> RunQaResponse

**2. prost 把 proto3 枚举字段生成为 i32**，而代码把 `req.source_lang`
当 `LanguageCode` 枚举直接用（4 处类型不匹配）。现补显式
`lang(i32) -> LanguageCode` 转换。

**3. `CatsError` 上没有 `error_code()`**，实际方法名是 `code()`。

**4. `ai_gateway.rs` 一个 move-after-borrow**：target_text 移进结构体后
又在下一个字段借用它。改成先算长度再移动，语义不变。

**5. 依赖缺失**（这些代码从没编译过，所以没人发现 Cargo.toml 少东西）：
  common          + actix-web / tonic / sqlx
  cats-rbac       + actix-web / uuid
  translation-core + async-trait / uuid
  worker-service  + cats-rbac / uuid

**6. worker-service**：`tick` 是私有函数但 `handlers.rs` 要调它；
`mark_qa_blocked` 返回 `PgQueryResult` 却声明 `Result<(), _>`。

这类错误在「代码写完但没编译」的仓库里可以潜伏任意久 ——
它只在 cargo build 的那一刻存在。每一轮修复都是新信息。

## 现在真的在跑的东西

**translation-core**：tonic gRPC server 监听 `GRPC_BIND_ADDR`（50051，
架构书 §4.1），承载 `TranslationCoreServiceImpl` 的 4 个 RPC
（MatchTM / TranslateSegment / RunQA / BatchTranslate）；
另有 HTTP `/healthz` 监听 `BIND_ADDR`（8080），与其余 service 约定一致。
两个 runtime 隔离（gRPC 用 tokio，healthz 用独立线程的 actix System），
因为把 actix 的 HttpServer 和 tonic 塞进同一个 runtime 是已知的坑。

**worker-service**：`DATABASE_URL` 缺失则 fail-fast（不打印值），
构造 PgPool，后台跑 `run_scheduler_loop`（抢占 pending→in_progress
→派发→回写），注册 `/healthz` `/readyz` `POST /v1/worker/tick`。

**common / cats-rbac**：`error.rs` 与 `service_helpers.rs` 进编译，
并加根路径 re-export（`cats_common::CatsError` 与
`cats_common::error::CatsError` 两条路都通，不强迫 6 个 crate 改写 import）。
